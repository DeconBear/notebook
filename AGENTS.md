# AGENTS.md

Guide for AI agents working in this repository. Covers the non-obvious architecture, conventions, and gotchas that aren't apparent from reading a single file.

## Project overview

**notebook** is a Chinese-language illustrated notebook published as a [VitePress](https://vitepress.dev) static site (formerly *learn-ai*). Content lives under `docs/`, grouped by domain (machine learning, deep learning, CV, NLP, RL, systems, scientific computing, world models, algorithms, papers, **ROS 2**)—not a single `ai/` bucket. Most chapters pair illustrated prose (`index.md`) with runnable Python (`code/demo.py`) and a guided exercise (`code/exercise.py`). ROS 2 lessons are Markdown-only; their colcon workspace is `workspaces/ros2-humble/`.

- Site URL: deployed at `https://<user>.github.io/notebook/` (note the `/notebook/` base path).
- All content is written in **Chinese** (`lang: 'zh-CN'`); code comments are in Chinese. Keep new content in Chinese unless told otherwise.

## Essential commands

```bash
# Site (Node 20, see deploy.yml)
npm install
npm run dev        # syncs public/code then VitePress dev
npm run build      # syncs public/code then build to .vitepress/dist
npm run preview    # preview the built site
npm run gen-toc    # regenerate the README directory listing from docs/

# Scaffold a chapter (sidebar picks it up automatically)
npm run new-chapter -- ml/foundations kernel-methods --title "核方法入门" --order 25

# Python code samples (CPU by default; GPU optional)
pip install -r requirements.txt
cd docs/ml/foundations/ai-overview/code && python demo.py
cd docs/ml/foundations/ai-overview/code && python exercise.py

# Special chapter with CLI flags
cd docs/nlp/transformer/code && python nanogpt.py            # CPU ~15min
cd docs/nlp/transformer/code && python nanogpt.py --gpu      # GPU
cd docs/nlp/transformer/code && python nanogpt.py --generate # load & generate
```

There is **no test suite** and no linter configured. "Testing" a code change means running the relevant `demo.py` / `exercise.py` and confirming the output/figures look right. Verifying a docs change means `npm run build` (and ideally `npm run dev` to eyeball the page).

Deploy is automatic via `.github/workflows/deploy.yml` on push to `master`/`main` (GitHub Pages, `cancel-in-progress` concurrency).

## Filesystem is the outline (add/remove a folder = add/remove a chapter)

Do **not** edit `.vitepress/config.mts` to register chapters. The sidebar is generated by [`scripts/lib/docs-tree.mjs`](scripts/lib/docs-tree.mjs) from:

- `docs/<path>/_meta.yaml` — a **group**: `title`, `order`, `collapsed`
- `docs/<path>/index.md` frontmatter — a **chapter**: `title`, `order`, optional `legacyPaths`

`order` uses gaps (10, 20, 30…) so a new chapter can insert with `15` without renaming neighbors. Folder names are short slugs (`ai-overview`), not `s01_...`.

**Add a chapter:** create the folder (or `npm run new-chapter`) under the right domain. Restart / refresh `npm run dev`.

**Delete a chapter:** delete the folder. If an old public URL must keep working, append it to [`docs/_gone.yaml`](docs/_gone.yaml).

**Do not** resurrect `snippets/` or hand-edit `public/code/` — see below.

## Code: one source, generated downloads

Canonical Python lives only in the chapter folder (`docs/.../<slug>/code/*.py`). VitePress pages include it directly:

```
<<< @/ml/foundations/ai-overview/code/demo.py
```

(`srcDir` is `docs/`, so `@/` is `docs/`.)

`npm run sync-code` (hooked into `dev` and `build`) copies those files to `public/code/<same relative path>/` for the Download button (`/notebook/code/ml/foundations/ai-overview/demo.py`). Chapters with `legacyPaths` also get a copy at `public/code/<old-slug>/` so old download URLs still work.

When you edit a chapter's code, edit **only** `docs/.../code/`. Do not maintain a second or third copy.

## VitePress configuration quirks (`.vitepress/config.mts`)

- **`base: '/notebook/'`** — every internal URL is prefixed with `/notebook/`. Keep this in mind when adding links; root-relative markdown links like `/ml/foundations/ai-overview/` are preferred over `../other-chapter/` across domains.
- **`srcDir: 'docs'`** — published markdown lives in `docs/`. Repo-root `README.md` is GitHub-only.
- **`publicDir`** points at the repo-root `public/` (not `docs/public`).
- **`ignoreDeadLinks: true`** — broken links will **not** fail the build. Check links manually when restructuring.
- **`srcExclude: ['README.md', '**/image_prompts.md', '**/CODE.md', '**/_gone.yaml', '**/_meta.yaml']`**
  - `image_prompts.md` — internal image-generation notes (also gitignored).
  - **`CODE.md`** — dev-only run log in some chapters; never published.
- **Mermaid** is enabled via `vitepress-plugin-mermaid`. The homepage uses a **domain-level** mermaid map so adding a chapter does not require editing that diagram.
- **Math** is on (`markdown.math: true`). Use `$...$` / `$$...$$`. Don't strip it.
- **Code blocks show line numbers** (`markdown.lineNumbers: true`).
- **`buildEnd`** writes HTML redirects from each chapter's `legacyPaths` (including `code-demo` / `code-exercise` / `nanogpt`) so old `/s01_ai_overview/` URLs still land.

## Standard chapter structure

```
docs/<domain>/.../<slug>/
├── index.md            # Main illustrated article
├── code-demo.md        # Walkthrough; embeds <<< @/<path>/code/demo.py
├── code-exercise.md    # Exercise guide
├── CODE.md             # Dev-only run report (some chapters; excluded from build)
├── code/
│   ├── demo.py
│   └── exercise.py
└── images/
```

Group folders (`docs/ml/`, `docs/ml/foundations/`, `docs/algorithms/graph/`, …) contain `_meta.yaml` and child folders, not a lesson `index.md`.

**Exceptions:**
- `docs/cv/vit/` has **no** `exercise.py` / `code-exercise.md` — only `vit_demo.py` and `code-demo.md`.
- `docs/nlp/transformer/` has extra `nanogpt.py` and `nanogpt.md`.
- `docs/systems/multimodal/images/samples/` ships real JPG samples for the CLIP demo.
- `docs/papers/placeholder/` has no `code/` yet.
- `docs/ros2/` lessons have **no** `code/demo.py`. Runnable packages live in `workspaces/ros2-humble/src/` (outside VitePress `srcDir`). See [ROS 2 tutoring](#ros-2-tutoring) below.

## Code conventions

- Every script starts with `# -*- coding: utf-8 -*-` and a large triple-quoted docstring framed by `===` lines.
- **Figures are saved into the chapter's own `images/` directory using a script-relative path**:
  ```python
  _SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
  _IMAGES_DIR = os.path.join(_SCRIPT_DIR, '..', 'images')
  os.makedirs(_IMAGES_DIR, exist_ok=True)
  ```
- **Chinese font setup for matplotlib** is required or Chinese labels render as boxes. `exercise.py` files set:
  ```python
  matplotlib.rcParams['font.sans-serif'] = ['Microsoft YaHei', 'SimHei', 'DejaVu Sans']
  matplotlib.rcParams['axes.unicode_minus'] = False
  ```
  `demo.py` files typically set just `axes.unicode_minus = False`.
- **Fixed random seeds** (`np.random.seed(42)` / `torch.manual_seed`) — keep seeds stable when refactoring.
- Code is **CPU-first by default**; GPU is opt-in (see nanogpt `--gpu`).
- Comments explain *why* (intuition), not just *what*. Prefer NumPy-only for foundational ML/DL chapters; reach for PyTorch where the chapter is about those frameworks.

## Image naming convention

Illustrations in `<chapter>/images/` follow `<prefix>-<NN>-<slug>.png` (existing files keep their names; do not mass-rename). Generated output figures from `demo.py` use plain slugs: `perceptron_results.png`, `loss_curve.png`. Alt text in `index.md` is descriptive Chinese.

## Python environment

`requirements.txt` is a **single union list** — install it once. Some chapters optionally call the OpenAI API or download HuggingFace models — see `.env.example`. Absence should degrade gracefully, not crash.

Downloaded ML weights are gitignored via `docs/**/models/` (not `**/models/`, so ROS robot models under `workspaces/` stay tracked). Also gitignored: `**/nanogpt_model.pt`, `**/input.txt`, `bert_sentiment_checkpoints/`, `data/`, and colcon `build/` `install/` `log/` under `workspaces/`. Do not commit these.

## Git conventions

Recent commits use **Conventional Commits** in English: `docs:`, `chore:`, `feat:`, `fix:`. Keep the subject under 72 chars. Never commit `.claude/`, `.env`, build output, or downloaded models.

## Working effectively in this repo

- Edit Python only in `docs/.../code/`. `npm run sync-code` refreshes `public/code/`.
- Adding a chapter: drop a folder under the right `docs/<domain>/` (with `index.md` frontmatter `title` + `order`) or use `new-chapter`. Then `npm run gen-toc` if the README listing should update.
- Cross-chapter links should be site-root paths: `[PINN](/science/pinn/)`. Cross-chapter images must stay relative file paths so VitePress can bundle them.
- **`npm run build` passing ≠ correct.** Because `ignoreDeadLinks: true`, visually verify with `npm run dev` / `preview`.
- **Keep math and Mermaid intact.**

## ROS 2 tutoring

When the learner is studying ROS 2 (or pastes `workspaces/ros2-humble/TUTOR_PROMPT.md`):

1. Read [`workspaces/ros2-humble/AGENTS.md`](workspaces/ros2-humble/AGENTS.md) and [`docs/ros2/overview/`](docs/ros2/overview/).
2. `$ROS_WS` is `workspaces/ros2-humble` (not the notebook repo root).
3. Teach lesson-by-lesson from [`docs/ros2/env/`](docs/ros2/env/) through `rviz-launch`. One lesson per reply.
4. Code lives in `workspaces/ros2-humble/src/`. After edits: `colcon build` then `source "$ROS_WS/install/setup.bash"`.
5. Run or guide `workspaces/ros2-humble/scripts/check_env.sh`. Ubuntu 22.04 + Humble.
6. Do not start with DDS/PID unless the current lesson needs it. Lessons 10–12 need a GUI.
7. Optional progress file: copy `workspaces/ros2-humble/progress.template.md` → `progress.md` (gitignored).
